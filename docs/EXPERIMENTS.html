Original research report ↗

Experiments, flowcharts, and expected results

Specification snapshot: 2026-10-21. This guide connects the mathematical specification and exact metrics to the existing production phase protocol. Diagrams distinguish executable work from proposed research. All numerical results below come from retained repository evidence, rather than newly executed training.

1. Experimental logic

The first question is whether the data, target, training, and state handling work. The principal research question is whether a structured hybrid improves fidelity over a capacity-matched TCN while meeting a runtime budget. Reference transfer is a later question requiring a trained encoder and independent cross-content evaluation.

The code automates generation, audits, training, held-out evaluation, CPU screening, optional supported ONNX export, and engineering gates. Parameter matching, multi-seed inference, bootstrap analysis, transfer, native deployment, and human studies are not automated by the current suite.

3. Deep learning and architecture flowcharts

3.1 Training and validation

Training minimizes waveform and spectral loss; checkpoint selection uses validation ESR. Test data do not enter the optimizer or select the epoch. Revisiting this smoke test during development is acceptable as an engineering practice, but a confirmatory study needs fresh reserved test sources.

3.2 Causal TCN and conditioning

Each block also adds its own incoming features; the diagram shows one representative block followed by repetition. The shallow conv1d has one unconditioned block. The unconditioned TCN omits FiLM. No block accesses future audio.

3.3 Three-branch hybrid — implemented prototype

hybrid_no_gru removes the recurrent path; hybrid_no_fir removes the FIR path. Each gets a two-branch router. Parallel paths provide distinct inductive biases, but the experiment must establish whether they learn useful complementary behavior.

3.4 Reference transfer — proposed, not implemented

This experiment must use references whose source content differs from the processed source, otherwise a content-memorizing encoder can appear successful. The proposed mathematical contract also addresses latent collapse.

E8: execution/runtime — Python/finite-context export available Offline versus regular/irregular blocks; PyTorch versus ONNX, later native Correct state preserves output; GRU can raise CPU cost Parity, screening thresholds, then sustained native and allocation gates
E9: perceptual and plugin acceptance — tooling only Blind target/model discrimination; native plugin in hosts Objective improvements may or may not reduce audible differences Preregistered listening study; appropriate group analysis; validator/host evidence

Expected outcomes are directional hypotheses. A failed or inconclusive E3 is a valid research result. E5 does not establish a neural advantage by beating identity while losing to direct convolution. Removing a branch changes parameter count and compute, so distinguish mechanism evidence from an equal-capacity architecture claim.

For a conditioning study, include fixed-preset models to distinguish parameter sharing from the benefit of explicit controls. For spectral-loss ablations, compare MSE-only to MSE+MR-STFT with the same seeds and budget; waveform and spectral rankings can differ. Temporal FiLM, no-conditioning hybrid, and loss ablations remain implementation work.

5.1 Current automated engineering gates

The automatic quality gates do not threshold MR-STFT or LSD; those remain reported metrics. If export evidence is absent it is not evaluated by assess; that absence cannot satisfy a release export requirement. Every automated gate report explicitly records production_ready: false.

5.2 Research and release gates

The production plan requires more than the automated gates: source-bootstrap comparisons and multiple families/seeds, real capture inspection, zero native deadline misses over at least ten minutes, golden native parity, explicit state/allocations review, a listening study with at least 20 listeners and 20 trials each, VST3 validation, named host checks, and independent reproduction.

The hybrid study's 10% improvement target is a research decision rule, not a forecast. The larger research configuration alone does not implement it. Declare parameter matching, primary metric aggregation, uncertainty analysis, and multiplicity handling before revealing final tests.

All models passed relaxed smoke quality criteria; none of these ESR values meets the research absolute threshold of 0.1. The simpler TCN has the best recorded ESR and MR-STFT. Static conditioning and extra branches did not improve this small experiment. This is compatible with a memoryless target and limited optimization; it does not establish which architecture will generalize best to captures or long-memory effects.

Maximum stream error was zero or about or less. A separate conditional-TCN end-to-end run recorded ONNX error at block size 128. Recurrent models failed the isolated Python p99 budget; the full hybrid reached 1.306 times the callback deadline at its worst p99. This calls for runtime work, but is not a measurement of a future native implementation.

The retained report records 38 passing tests, a WAV render, and a three-trial ABX package. No human responses were collected. The suite did not test hybrid superiority: models were not capacity matched, only one seed and one memoryless family were studied, and three test sources give little information about uncertainty.

7. Reproducing and extending experiments

Install the project as described in the root README. Use a new output directory for every run; generation and training refuse nonempty destinations.

# Reproduce the seven-model synthetic engineering suite.
python -m neural_fx run --config configs/smoke.json --output runs/docs-smoke-suite --suite

# Single configured conditional TCN, including supported ONNX export.
python -m neural_fx run --config configs/smoke.json --output runs/docs-smoke-export --export

# Larger one-seed synthetic suite; this is not the complete hybrid study.
python -m neural_fx run --config configs/research.json --output runs/docs-research-1337 --suite

A suite can complete with exit code 1 because a model missed an engineering gate. Inspect status.json, comparison.csv, and model gate reports; an execution exception is a different failure. Reproduction timing will vary with hardware and load.

For cabinet/reverb, make and retain a copied config with an explicit effect change. For three-seed research, retain separate config copies with seeds 1337/2027/3407 and separate run directories. Keep all compared architectures on identical data within each seed, and freeze whether cross-seed data are held fixed or regenerated: the current config seed controls both source generation and model training, so changing it changes both. A study isolating optimizer variability needs separate data and training seeds in a future implementation.

Imported captures use individual stages rather than run, which always generates synthetic data:

python -m neural_fx prepare --index data/raw/own_captures/index.jsonl --output data/processed/docs-captures
python -m neural_fx verify --data data/processed/docs-captures
# First retain configs/captures.json with matching effect/sample rate and crop lengths.
python -m neural_fx train --config configs/captures.json --data data/processed/docs-captures --output runs/docs-capture-tcn
python -m neural_fx evaluate --checkpoint runs/docs-capture-tcn/best.pt --data data/processed/docs-captures --output runs/docs-capture-tcn/evaluation
python -m neural_fx benchmark --checkpoint runs/docs-capture-tcn/best.pt --output runs/docs-capture-tcn/runtime.json

configs/captures.json is an example filename to create for the actual capture dataset, not a supplied config. Extend the current drive/mix mapping explicitly for devices with other controls. Preserve the dataset snapshot: evaluation checks it against the checkpoint's manifest hashes.

To prepare and score a listening package after evaluation:

python -m neural_fx abx-package --evaluation runs/docs-capture-tcn/evaluation --output runs/docs-listening
python -m neural_fx abx-score --answers runs/docs-listening/private/answers.json --responses path/to/completed-responses.csv --output runs/docs-listening/scores.json

Only distribute the public package to listeners. A confirmatory listening study needs sufficient selected stimuli and the protocol described in metrics, beyond these packaging commands.

8. Evidence required for a completed study

Retain the protocol/configurations, Git and source identities, dataset provenance and hashes, independent-source counts, selected checkpoints/epochs, all per-pair metrics, source aggregates, seed-level results, failed gates, and fixed audio examples. Report fidelity alongside parameter count, finite context, recurrent state, latency, and timing environment. Add uncertainty intervals and study exclusions when those analyses are implemented.

State which hypotheses were supported, rejected, or unresolved, and keep exploratory revisions separate from the completed test. Native deployment and perceptual claims require their own evidence even when every synthetic engineering gate passes.
