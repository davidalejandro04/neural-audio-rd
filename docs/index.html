    Neural audio research documentation

    Electric guitar demo: real CC0 DI recordings through live distortion, presets and measured checks.

    Current development preview: see native standalone/VST3, paired-reference inference and measured acceptance. The synthetic extension was executed on 2026-10-22; sustained timing failed and external acceptance remains open.

    Start learning: the twelve-lesson HTML course teaches these foundations with interactive plots, worked mathematical examples, exercises, and a capstone. It works offline.

    This documentation connects the project's research questions to its DSP, neural models, equations, experiments, and evidence. Specification snapshot: 2026-10-21.

    Document Contents
    Theoretical foundations and mathematical specification System identification, sampling, convolution, nonlinearities, neural networks, exact implemented architecture, optimization, state, and proposed extensions
    Metrics and statistical interpretation Exact waveform/spectral formulas, aggregation, runtime and export metrics, ABX statistics, and future effect-specific diagnostics
    Experiments, flowcharts, and expected results Experiment sequence, model/training/evaluation flowcharts, reproducible commands, acceptance thresholds, observed results, and falsifiable expectations
    Research production pipeline Existing phase protocol, production acceptance criteria, and implementation backlog

    Read the theory first, then metrics and experiments. Each page is an HTML document with equations and flowcharts embedded as SVG. Everything renders offline, without external scripts or a documentation server. The original HTML and Markdown research reports remain the project motivation. Their HyNeFX-RT and CHNFX proposals differ: the implemented hybrid is a three-branch prototype related to the HTML proposal, without a reference encoder or long convolution engine.

    Throughout these documents:

    • Implemented describes behavior in src/neural_fx, whether or not a large experiment has run.
    • Measured identifies recorded evidence, principally the initial results and their JSON snapshot.
    • Required identifies an acceptance target from the phase protocol or checked-in configurations.
    • Proposed identifies mathematical designs or experiments requiring implementation and protocol decisions.

    The source files define current executable behavior. The phase protocol defines research acceptance. Expected results are hypotheses, not measurements or guarantees. The larger research configuration is available, but the retained initial evidence is a one-seed synthetic distortion smoke study.
