All models passed streaming equivalence. Gates use test ESR, not the validation ESR printed beside training progress. Unconditioned baselines receive the same dry source at multiple drive settings without access to drive, so they cannot reproduce every target exactly. The principal hybrid comparison must use a conditioned baseline.

The full hybrid has a seen-controls pair-median ESR of 0.000573 and held-out-controls ESR of 0.3369; conditional TCN has 0.000387 and 0.01991 respectively. Low validation error on seen presets does not demonstrate control interpolation. Training only includes active mix=1 and bypass mix=0, while test includes intermediate mix; both drive and mix change in the held-out presets, so these data do not isolate the cause. Conditioning on mix as well as applying an explicit mix residual is a possible contributor, not an established explanation. Test it in a future development ablation without selecting on the final test set.

P3: prepared matched study

  • Conditioned TCN: 19 channels and 6,138 parameters. Full hybrid: 16 channels and 6,011 parameters. Difference: 2.1%, within the 10% tolerance.
  • Two synthetic target families: distortion and cabinet. Three training seeds: 1337, 2027 and 3407. Data seed 8181 is fixed across training seeds and is different from the reviewed pilot.
  • Four model fits per configuration: matched conditional TCN, hybrid without GRU, hybrid without FIR, full hybrid. Six configurations mean 24 model fits. Ablations retain branch widths and have fewer parameters; they are not individually parameter matched.
  • Each fit retains the research budget: 60 train, 15 validation and 20 test sources, one second/source at 48 kHz, 60 epochs, CPU execution. The prospective configs retain existing quality/timing thresholds.

Start with one configuration. This is a substantive CPU workload; training is not launched by the planner.

python -m neural_fx run --config configs/p3-study/distortion-seed-1337.json --output configs/p3-study/runs/distortion-seed-1337 --suite --export

Inspect its gate reports and held-out controls before deciding how much additional compute to spend. To complete the preregistered study without changing its configs, run this in PowerShell:

& .\configs\p3-study\run.ps1

The runner skips completed, config-matching runs, including completed runs whose engineering gates failed. It stops on incomplete or conflicting output, and on execution errors. It does not resume a partially trained model. The runner requests ONNX export only for the already supported nonrecurrent adapters; GRU variants still need a persistent-hidden-state adapter.

Analysis can also be run separately:

P3 acceptance and interpretation

Within each source, average active presets. Average these source scores across training seeds, then take the median over sources. Resample source and seed indices independently using identical resamples for both models; report percentile 95% paired bootstrap intervals for the error reduction. These are exploratory intervals with only three training seeds, not a publication guarantee. Report held-out controls separately.

Each of two families needs at least a 10% reduction in both ESR and MR-STFT, bootstrap intervals above zero improvement, no deterioration in held-out-controls point estimates, the parameter match, the minimum source/seed counts, and passing quality, streaming and runtime checks. A rejected or inconclusive hybrid result is valid. The current model is not expected to pass by assumption.

The analyzer separates quality-hypothesis support from runtime acceptance and rejects mismatched configs, checkpoints or dataset snapshots. It reports missing study runs as incomplete. P3 synthetic acceptance always leaves production_ready=false.

What follows after this study

  1. Data and P2 replication: inspect licensed real DI/effect pairs with the existing importer. Synthetic cabinet experiments do not establish actual hardware fidelity. Repeated training seeds on a fixed dataset quantify training variability, not variability across datasets.
  2. P5 runtime: profile and implement an explicit persistent-GRU export adapter or a native recurrent runtime. Preserve streaming behavior, test native golden vectors, then measure sustained callback deadlines. The current short Python screen cannot accept a VST3 release.
  3. P4 transfer: add a paired-reference encoder and source-disjoint transfer protocol to an adequately performing controllable backbone. Hybrid rejection does not prevent using the stronger conditional TCN as that backbone, but any changed hypothesis needs a new protocol.
  4. P6 release: build the native standalone/JUCE plugin, collect human listening results, run the VST3 validator and host smoke tests, and verify dataset/model/SDK notices. ABX packaging is implemented; actual listener results and plugin validation are not.
