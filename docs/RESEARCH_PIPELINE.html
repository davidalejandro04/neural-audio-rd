Research production pipeline

Protocol version 1, 2026-10-20. Sources: HTML research description and Markdown research description. The HTML's three-branch HyNeFX-RT is the candidate architecture; CHNFX in the Markdown is the earlier two-branch proposal. Neither name establishes novelty.

The repository began with these two descriptions and no implementation. This protocol separates implemented tooling, executed experiments, and accepted research/release gates. A successful command does not establish a research claim.

Implementation update, 2026-10-22: the native/reference guide records the executed synthetic P4 baseline and P5/P6 preview work. The original exit criteria below are preserved; implementation does not imply acceptance.

Experiment discipline

Start with distortion; repeat the same protocol for cabinet IRs, hardware distortion/amp pairs, then long reverb. Keep analytic DSP controls throughout. A synthetic analytic oracle knows the generating target; its perfect score is an integrity check, not a deployable learned baseline or fair unknown-device estimate.

Synthetic splits contain independently generated harmonic/noise performances and gain levels. Train/validation have drive 0.1/0.5/0.9 at mix=1 and a bypass example. Test includes those settings on unseen sources plus unseen (drive, mix) combinations (0.3,0.65) and (0.7,0.4). This is interpolation testing. It is not extrapolation, real guitar generalization, or real hardware validation. The toy tanh target is not oversampled; no alias-suppression claim is supported.

preregistered_config.json is written before generation/training. It records seed, dataset size, training budget, architectures and gates. For a publishable study, commit the protocol, code and parameter-matched suite before opening final test results. Reserve final test sources separately from development data, including this smoke run. Freeze and hash external dataset selections, source splits, control normalization and exclusions. No automatic dataset download or redistribution is performed.

Training is CPU-only in this first reference implementation, seeds Python/NumPy/PyTorch, uses deterministic operations and one PyTorch thread, optimizes MSE + configured MR-STFT, clips gradients, and selects best.pt by active validation ESR. Random training crops include preceding finite context and use a short GRU warmup, not full-performance recurrent history. This is insufficient for long-memory experiments; implement stateful truncated backpropagation before studying reverb/amplifier dynamics. Current FiLM is static parameter conditioning, not Temporal FiLM.

Evaluation excludes bypass from quality aggregates. It averages each metric across active presets within each source, then reports the median across sources. It also reports per-pair medians by seen/held-out control regime. ESR is unweighted error energy / target energy; silence ESR is undefined (null). MR-STFT is mean spectral convergence plus mean absolute natural-log magnitude discrepancy at FFT sizes 64/128/256 and hop N/4; LSD is RMS dB magnitude error across frequency, averaged over frames at FFT 256/hop 64. These short windows serve the smoke task; freeze effect-appropriate larger windows for research comparisons. Audio is never independently peak-normalized. Loudness-matched listening is a separate condition.

Every checkpoint has its complete config, selected epoch and manifest hashes. Run directories additionally contain environment versions, Git commit/status, manifest audit, training history, per-pair test metrics, audio examples and runtime measurements. Outputs are immutable by convention: generation/training refuse nonempty destinations. Re-evaluation can update evaluation artifacts for the same checkpoint; archive reports when changing metric definitions. Missing export/native/listening evidence never counts as a passing release gate.

Execution and decision gates

configs/smoke.json runs 8 train / 3 validation / 3 test sources, 62 pairs and 12 epochs. Its relaxed ESR <=0.5 and <=0.95 times identity gates are engineering checks. configs/research.json defines a larger synthetic baseline with stricter ESR <=0.1 and <=0.8 times identity. Neither substitutes for the P3 hypothesis test or real recordings.

run saves status after every model and emits comparison JSON/CSV. It completes all requested models even if a quality/runtime gate fails; it returns exit status 1 if any model fails. Execution errors record the failed stage and stop. --export exports finite-context and recurrent architectures and checks ONNX Runtime parity; recurrent graphs explicitly carry hidden state between blocks. Export is opt-in because it requires extra dependencies. Benchmark results identify Python screening as such and include mean/p95/p99/worst time and missed deadlines. A passing p99 alone does not satisfy sustained native real-time acceptance.

Deferred implementation backlog, in order

  1. Acquire and inspect licensed real DI/effect pairs. The two reports suggest different external datasets; verify item licenses, waveform pairing and consent/provenance before adoption. No imported license assertions from the reports are treated as verified.
  2. Train longer baselines over three seeds and parameter-match the TCN to the hybrid. Add Temporal FiLM, loss ablations, source-bootstrap comparisons and effect-specific alias/IR/decay metrics.
  3. Replace the short dense FIR prototype with long IR bases and partitioned convolution. Add stateful truncated backpropagation and long-tail fixtures.
  4. Extend the executed paired-control reference baseline to the preregistered multi-family neural transfer study. Keep known-DSP and neural-decoder measurements separate.
  5. Persistent GRU export and native parity are implemented. Resolve sustained timing failures, audit runtime-internal allocations and benchmark actual target-host callbacks before acceptance.
  6. Native standalone, JUCE VST3 and official validator checks are implemented. Complete named-host and listener studies, clean-machine reproduction and release notices. Distribution license choice remains with the repository owner.

Implementation references: PyTorch 2.11 ONNX exporter and Conv1d. The ONNX adapter uses dynamo=True and explicit rolling history.
